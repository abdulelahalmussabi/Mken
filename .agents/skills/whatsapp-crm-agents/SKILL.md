# وكلاء واتساب CRM (WhatsApp CRM Agents)

مهارة مرجعية لعشر قدرات. اقرأ القسم المعني عند الحاجة. القاعدة: واتساب مكّن = WhatsApp Cloud API عبر `api/whatsapp-webhook.js` (استقبال) + `api/cron-whatsapp.js` (إرسال مجدول) + `js/whatsapp-automation.js` و`js/admin-whatsapp-logs.js` (إدارة) + n8n workflows في `data/n8n-whatsapp-*.json` + الذكاء الاصطناعي عبر `js/mken-copilot.jsx`. راجع أيضاً مهارة `whatsapp-integrations` لتفاصيل API.

---

## 1. معالجة اللهجات المحكية (NLP & Dialect Processing)

**متى:** فهم رسائل عربية عامية (سعودي/خليجي/مصري...)، ردود قصيرة، أخطاء إملائية.

**خطوات مرجعية:**
1. رسائل المستخدم النموذجية قصيرة وعامية — اعمل normalize قبل الإرسال للـAI: إزالة التشكيل، توحيد الـhamza/alef، trim، إزالة tashkeel.
2. استخدم persona واضح (راجع commit `feat(whatsapp-ai): professional CS persona`) — "سعد مساعدك الذكي" البراند الحالي.
3. للكلمات المحلية: ابني قاموس مرادفات (مثلاً "حجز/أبغى موعد/عندي مناسبة" → intent = booking).
4. خصّص `maxOutputTokens` كافٍ (commit `201d2d4` رفع 400→1024 لوقف قطع الرد العربي).

---

## 2. إدارة حالة المحادثة (Session State Management)

**متى:** تذكّر تفاصيل العميل عبر الرسائل المتعددة، تجنّب إعادة السؤال.

**خطوات مرجعية:**
1. خزّن حالة لكل `phone_number` في Supabase (جدول sessions): آخر intent، المتغيرات المجمّعة (اسم، خدمة، وقت)، آخر رسالة، مرحلة القمع.
2. قبل توليد الرد: حمّل سياق الجلسة + آخر N رسالة (memory).
3. بعد الرد: حدّث الجلسة بالحقول الجديدة.
4. ضع TTL/انتهاء صلاحية للجلسة (مثلاً 24 ساعة) لإعادة التأهيل.
5. راجع `data/n8n-whatsapp-ai-sales-agent.json` لنمط الذاكرة الموجود.

---

## 3. حجز واستعلام المواعيد (Appointment Scheduling)

**متى:** ربط واتساب بتقويم، تأكيد موعد، استعلام أوقات متاحة.

**خطوات مرجعية:**
1. مكّن لديه أساس: `data/appointments.json` وGoogle integration عبر `api/_lib/google-auth-helper.js` و`api/google-business.js`.
2. للتأكيد: تحقّق من التوفر → احجز atomically → أرسل تأكيدًا للعميل + تذكير cron.
3. أرسل تذكير قبل الموعد عبر `api/cron-whatsapp.js` (idempotent).
4. للإلغاء/إعادة الجدولة: حرّر الفتحة، حدّث السجل، أرسل تأكيدًا.

---

## 4. تصنيف وتأهيل الفرص (Lead Scoring & Qualification)

**متى:** تقييم جدية العميل، تصنيف تلقائي في قمع المبيعات.

**خطوات مرجعية:**
1. عرّف معايير التأهيل لكل tenant (خدمة مطلوبة، ميزانية، توقيت، حجم).
2. احسب score (0-100) من إجابات العميل + سلوكه (سرعة الرد، عدد الرسائل).
3. صنّف: cold / warm / hot / won. خزّن في Supabase مع timestamp.
4. توجيه hot leads للتصعيد البشري فوراً (انظر القسم 7).
5. للمتابعة: cron يراسل cold/warm بعد فترة (راجع `data/n8n-whatsapp-dispatch-workflow.json`).

---

## 5. التكامل الحظي مع CRM (Real-time CRM Sync)

**متى:** مزامنة جهات اتصال وتفاعلات مع HubSpot/Salesforce/Zoho.

**خطوات مرجعية:**
1. أبقِ Supabase كمصدر الحقيقة الأساسي (source of truth) لكل tenants.
2. للمزامنة الخارجية: webhook على تغيير العميل → push إلى CRM الخارجي.
3. تعامل مع التعارض بـ"آخر تحديث يربح" + timestamp.
4. تجنّب التزامن الثنائي الاتجاه المعقّد ما لم يُطلب صراحةً.
5. اذكر دائماً: معظم tenants SMB لن يحتاجوا HubSpot — ابدأ بـSupabase + واجهة admin.

---

## 6. إرسال الرسائل التفاعلية (Interactive Messaging)

**متى:** قوائم، أزرار، ردود سريعة وفق WhatsApp Business API.

**خطوات مرجعية:**
1. استخدم `type: "interactive"` مع `button` / `list` في الـpayload.
2. القيود: حتى 3 أزرار لكل رسالة، عناوين قصيرة (<20 حرف).
3. must be approved template للرسائل خارج نافذة 24 ساعة.
4. اربط كل زر بـintent واضح لتسهيل معالجة الرد.
5. ارجع لـ`js/whatsapp-automation.js` لأنماط الإرسال الموجودة.

---

## 7. التصعيد الذكي للعنصر البشري (Human Handoff)

**متى:** استفسار معقد، عميل غاضب، صفقة hot، أو فشل الـAI.

**خطوات مرجعية:**
1. عرّف محفّزات التصعيد: score عالي، sentiment سالب، رسالة "مدير/مسؤول"، 2+ ردود فشل متتالية.
2. عند التصعيد: علّم الجلسة `status=handoff`، أرسل إشعاراً داخلياً (واتساب/بريد لفريق المبيعات)، وأوقف الرد الآلي.
3. أبلغ العميل: "سيعاودك الموظف فلان قريباً".
4. بعد التحويل: راقب الاسترجاع — إن لم يستجب أحد خلال X دقيقة، تذكير داخلي.
5. سجّل كل تصعيد في `js/admin-whatsapp-logs.js`.

---

## 8. معالجة الوسائط المتعددة (OCR & Voice)

**متى:** صور فواتير، رسائل صوتية، مستندات.

**خطوات مرجعية:**
1. الصور: حمّل media من WhatsApp Cloud API (media_url + token)، مرّر لـOCR (Vision API / Google / نموذج محلي).
2. الصوت: حمّل ogg، حوّل لنص (Whisper أو ما يعادله)، عالج النص كرسالة عادية.
3. خزّن الوسائط مؤقتاً، لا دائماً (تكلفة + خصوصية PDPL).
4. أبلغ المستخدم دائماً بما فهمته من الوسائط لتجنّب سوء التفسير.

---

## 9. التحقق من الهوية (OTP & Verification)

**متى:** تأكيد حجز/دفع/عملية حساسة، ربط رقم بالحساب.

**خطوات مرجعية:**
1. ولّد OTP عشوائي 4-6 أرقام، خزّنه بـTTL قصير (5-10 دقائق) مرتبطاً بـphone.
2. أرسله عبر واتساب (template approved مطلوب لـOTP).
3. تحقّق بمقارنة hashed، لا تخزّن plaintext أطول من اللازم.
4. rate-limit المحاولات (مثلاً 5/ساعة) لمنع brute force.
5. بعد التحقق: علّم الجلسة verified، اسمح بالعملية.

---

## 10. تحليل المشاعر (Sentiment Analysis)

**متى:** قياس رضا العميل، كشف الغضب، توجيه التصعيد.

**خطوات مرجعية:**
1. صنّف كل رسالة: positive / neutral / negative + score ثقة.
2. راقب التحوّل: عميل كان positive ثم negative = إشارة مشكلة.
3. negative + score عالي ثقة → تصعيد فوري (القسم 7).
4. خزّن السلسلة الزمنية للـsentiment للوحة الإدارة.
5. احذر: اللهجات قد تضلّل المحلّل — ادمج مع intent ولا تعتمد على sentiment وحده.

---

## قواعد الاستجابة

- ردّ بالعربية ما لم يُطلب غير ذلك.
- أسماء الملفات ومتغيرات البيئة (`WHATSAPP_TOKEN`, `VERIFY_TOKEN`...) حرفية.
- ميّز بين المبني فعلاً (whatsapp-webhook.js, cron-whatsapp.js) والمقترح.
- لا تنشر tokens في الواجهة أبداً — راجع `whatsapp-integrations` للأمان.
